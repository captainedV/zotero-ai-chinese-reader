# 设计说明（实现细节）

README 只讲"能做什么"，这里讲"为什么准"。全部结论都来自真实 Zotero + 真实论文的自动化测试。

## 1. 版面结构识别

抽出文本后先给每个块判定角色：标题、作者、摘要、章节标题、正文、图注、表注、表格数据、
公式、目录、页眉页脚、脚注、参考文献。**只有正文类内容会被翻译**：

- 表格只翻表标题，表格数据不翻（避免译文错位）；
- 公式、目录、页眉页脚、脚注、参考文献不翻；
- 字体档位（body / h1 / h2 / h3）由按字符数加权的字号直方图推出，而不是固定比例；
- 标题判定是严格的：长度上限、句末标点、编号例外，`2.1. Image-to-Image Translation`
  这类小节标题不会被粘进上一段；
- 图注（`Figure 1 | …`）与正文引用（`Figure 1(a) depicts …`）分开处理。

## 2. 段落不被切碎

- 行字号取"该行字符数最多的字号"（众数），行内公式 / 上标不会改变行字号，从而不会把
  一段切成两段；
- **标点优先**：句子没写完（不以句末标点结尾）就继续并入下一个正文块——跨缩进、跨栏、
  跨页，甚至跨过排序在中间的图内标签；
- 图注会收回自己的换行与续行；
- 被跨页接续的后半段在同一份文档里以"影子段落"存在，因此悬停任一页都能高亮同一张卡片。

实测（各 8 页，见 [segmentation](segmentation/)）：段末被截断的段落数
DeepSeek-V2 15→2、Xiao 双栏 27→5、DeepSeek-R1 11→1。

## 3. 成批翻译 + 上下文

- 连续段落打包进同一次请求（默认 2200 字符 / 6 段）；
- 每次请求附带论文标题、当前章节标题、前一段与后一段原文（标注为参考、不要求翻译）；
- 要求模型按条目 id 返回 JSON；返回不完整自动二分重试（6→3→1），不会写入半截译文；
- 批次按"离当前页的距离"排序，先填正在阅读的那一页。

实测：同一篇 103 个翻译单元从 103 次请求降到 18 次。

## 4. 数学公式

`content/scripts/latex.js` 把 LaTeX 转成 Unicode 与真正的上下标：
`c_t^{Q}` → cₜ^Q、`\mathbb{R}^{d_c'}` → ℝ^dᶜ′、`\sum_{i=1}^{n}` → ∑ᵢ₌₁ⁿ。
先 HTML 转义再替换，模型输出无法注入标记；未知命令原样保留。

## 5. 开关状态机

每个功能的状态由「本篇论文的开关意图」+「dock 里的真实任务」共同推导：
`off / ready / running / paused / done / error`。开关、状态行、工具栏图标、任务行都从这一个
状态渲染；无法启动（没配 Key、扫描版 PDF）时开关会自动弹回关闭。用户点击优先于迟到的
记录加载（epoch 机制）。

## 6. 可靠性

- 传输默认 `fetch`（流式），不支持时自动回退特权 XHR；设置里可手动切换；
- 流式 15 秒无数据 → 自动改非流式；推理模型输出被思考吃光 → 自动翻倍预算重试；
- 429 按服务器给的时间退避，并按「每分钟请求上限」节流；
- 失败常驻红色横幅（原因 + 实际请求地址 + 提示），不会一闪而过；
- 配置（provider/model/Base URL/Key）另存 0600 备份，偏好丢失时自动还原；
- 升级/降级不会清理偏好，只有真正卸载才会。
